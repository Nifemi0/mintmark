Mintmark documentation

Identity before inference.

Mintmark is a public identity and evidence registry for tokenized stocks on BNB Smart Chain. It helps someone begin with a familiar company, find every checked provider product, and inspect the exact contract and source behind each claim.

Open a live comparisonRead the source

Quick start

Find the product you actually mean.

  1. Search a company or ticker.Use NVIDIA, Tesla, Apple, NVDA, TSLA, AAPL, a fund, a keyword, or a complete BSC contract.
  2. Compare provider products.A shared stock ticker can resolve to separate Ondo, bStocks, and xStocks contracts. Each row remains a distinct product.
  3. Open the evidence record.Check the full contract, BscScan, issuer terms, onchain name and symbol, source differences, and public history.
  4. Check trading status.bStocks show a direct Binance Spot route when verified. An exact record may also show a detected BNB Chain DEX pool after Mintmark checks indexed liquidity; Ondo and xStocks are not assumed tradable without that evidence.
  5. Read live data in context.Exact-contract token-market coverage stays separate from the underlying-company report. Missing fields and provider inconsistencies remain visible.

Shareable discovery

Link directly to a comparison or record.

Put a familiar public ticker in the q parameter. Opening a record adds its exact 56:contract key while preserving the comparison context.

https://mintmark.nuvixes.studio/?q=NVDA#registry

The search parameter is for discovery. Mintmark still uses chain ID plus the complete contract address as product identity.

Integrate · API v1

Check a token in one request.

The v1 API is free, read-only, needs no key, and can be called from a browser or a server. Every token comes back in one shape: its exact contract, provider and issuer, underlying stock, provider halt status, Binance Spot pair, and source links.

One token by exact contract

curl https://mintmark.nuvixes.studio/v1/tokens/56/0xa9ee28c80f960b889dfbd1902055218cba016f75

Up to 100 contracts at once

Use this for a wallet's holdings or a token list. Each address comes back in the order sent as registered, pending_review (published by a provider, not reviewed yet), not_registered or invalid_address.

curl -X POST https://mintmark.nuvixes.studio/v1/tokens/lookup \
  -H 'content-type: application/json' \
  -d '{"addresses":["0xa9ee28c80f960b889dfbd1902055218cba016f75"]}'

From JavaScript

const res = await fetch('https://mintmark.nuvixes.studio/v1/tokens/lookup', {
  method: 'POST',
  headers: { 'content-type': 'application/json' },
  body: JSON.stringify({ addresses: walletTokenAddresses }),
});
const { results } = await res.json();
const stockTokens = results.filter((r) => r.status === 'registered');

  • Stable: within v1, fields may be added but are never renamed or removed. Breaking changes go to v2, announced in the daily report first.
  • Errors: always {"error":{"code","message"}} with a matching HTTP status.
  • Limits: 120 requests a minute per client; the x-ratelimit-* headers show what is left. Use the bulk lookup for many addresses.

Evidence model

Every label says what was actually checked.

Onchain observed

Mintmark read contract bytecode, name, or symbol from BSC RPC at the recorded time.

Issuer published

The provider published the identity, contract, or terms. Mintmark links that statement.

Third-party reported

Binance supplied the field. Provider and retrieval times remain attached to live market data.

Unverified

Mintmark has not independently inspected offchain backing, custody, or legal rights.

A working ERC-20 contract proves its onchain responses. It does not prove that shares are held, that products with the same ticker are equivalent, or that reported liquidity is executable.

Limits

What Mintmark does not claim.

  • The catalog is a dated, reviewed snapshot and can become stale.
  • Market fields are provider reports, not official exchange quotes or liquidity guarantees.
  • The wallet route checks 70 known contracts (24 Ondo and 46 bStocks) and does not scan every wallet asset.
  • Mintmark does not execute transactions, recommend investments, or verify custody.
  • A missing provider row is a data gap, not proof that a token is invalid or retired.
