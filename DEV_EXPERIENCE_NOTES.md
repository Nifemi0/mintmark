# Binance Web3 API integration notes

These are factual engineering notes for the builder's own developer experience report. They are not submission prose.

- **Public hosting check (30 September 2026):** The same Binance credentials returned an exact-contract NVIDIA company report from the local server. After the credentials were added as encrypted Vercel production variables, the deployed server received HTTP 200 with Binance business code `40304` and the message “Service not available due to compliance restriction” for both the RWA list and underlying-profile requests. The public report therefore remained unavailable. The variables were removed from Vercel and a no-key production build was redeployed. This is a provider restriction for that hosted request, not evidence of a signature or missing-key bug. No regional routing workaround was attempted.

- **29 September 2026:** No `OC_API_KEY` or `OC_SECRET_KEY` is configured locally. Signed Binance RWA requests cannot yet be exercised. The app's live cross-check remains pending and says so in the UI.
- **Authentication detail:** The signature pre-hash uses the full `/build/api/v1/...` path, including the encoded query. The [authentication page](https://web3.binance.com/en/dev-docs/authentication) calls omission of `/build` a common cause of invalid signatures.
- **Source bridge:** The [RWA Data documentation](https://web3.binance.com/en/dev-docs/catalog/web3-wallet/api/rest-api/rwa-data) lists Ondo BSC assets by chain ID and contract. Ondo's [contract addresses page](https://docs.ondo.finance/addresses) links an asset CSV with exact BSC contracts. The six selected contracts returned nonempty bytecode and matching ERC-20 name/symbol through public BSC RPC during the initial sync.
- **Data limitation:** An issuer asset list and an ERC-20 contract do not independently establish custody of the underlying shares. Mintmark labels that claim unverified.
- **Live RWA call (29 September 2026):** After credentials were configured, the signed BSC token-list request succeeded in about 2.8 seconds and returned 488 rows. All six curated Ondo contracts appeared once with matching platform, underlying ticker, and token symbol. Binance shortens their display names (for example, “Apple (Ondo)” versus the onchain “Apple (Ondo Tokenized)”). This is recorded as a source-specific name difference, not a contract identity conflict.
- **Discovery expansion:** The curated catalog grew from six to 24 BSC contracts after a user review showed that knowing a token ticker was too demanding. The fresh issuer CSV and BSC RPC checks passed for all 24, and a live Binance response agreed on every exact identity (18 display-name differences, six exact names, no missing or conflicting contracts). Browse areas and search keywords are clearly editorial navigation labels.
- **Cross-check behavior:** A Binance row counts as an exact match only when contract, platform, underlying ticker, token symbol, and token name agree. A display-name difference is shown separately. Missing values are marked incomplete; duplicate exact-contract rows or differing identity fields are conflicts. The browser shows the comparison time and links the API field definitions.
- **Query decision:** The call uses `GET /api/v1/dex/market/rwa/tokens?binanceChainId=56` without a platform filter. A platform-filtered response could hide an issuer conflict. Keep missing fields and duplicate identities visible.
- **Company report (29–30 September 2026):** The RWA underlying-profile response supplied company industry, description, and website; underlying-market supplied reference price, market cap, 52-week range, valuation, and dividend fields. The documented reference price derives from token price and must not be represented as an exchange quote. The market-candles route returned 30 daily **BSC token** closes. The UI keeps those two price concepts separate and timestamps each source.
- **Wallet pagination gap:** A known AAPLon holder had a nonzero balance confirmed through BSC `balanceOf`, but `GET /all-token-balances-by-address` returned 2,000 unrelated tokens in its first 20 pages and never reached AAPLon. Mintmark now uses `POST /token-balances-by-address` with its exact curated contracts in batches of 20. For the public example address, the targeted response returned the AAPLon balance and 18 supported nonzero holdings. This approach does not enumerate unknown tokens in a wallet; the interface says so.
- **Clock tolerance (30 September 2026):** The host clock lagged the Binance HTTP `Date` header by roughly four seconds. With network time added, a signed request failed with `40103` (timestamp expired). The documented `X-OC-RECV-WINDOW` header at 60,000 ms made the same targeted request succeed. The API secret stays server-side.
- **History scope:** The first version-history snapshot covers the 24 curated records. Future syncs append a version only when tracked identity fields change, or a token leaves or returns to the curated catalog. It does not reconstruct changes before the first snapshot.
- **Catalog expansion (30 September 2026):** The Ondo-linked CSV listed 450 BSC-addressed stocks and ETFs: 333 stocks and 117 ETFs. Batched BSC RPC checks confirmed bytecode and exact symbols for all 450. Three token-name differences (ETHA, GOOG, IREN) are retained as visible issuer/onchain discrepancies; FSOL differed only by trailing whitespace. The live Binance RWA list returned 362 exact name matches, 80 display-name differences, and eight exact contracts absent from that provider response. Absence from Binance is shown as a third-party data gap, not proof that an issuer token is invalid.
- **Image source:** The CSV's AAL image link pointed to ABT's image. Mintmark derives the official Ondo CDN image URL from the checked token symbol and downloaded all 450 PNGs. Logos remain a recognition aid, never identity evidence.
- **Wallet coverage after expansion:** Binance's targeted Wallet API accepts 20 contract pairs per request. The wallet flow remains explicitly limited to the original 24 enabled contracts (two requests); the 450-record directory is broader. This avoids implying that an address with no result lacks other Ondo holdings.
- **Three-provider catalog (30 September 2026):** The Binance signed BSC RWA list supplied 46 bStocks rows, with exact contracts, underlying tickers, and image URLs. The xStocks public asset API supplied 1,069 assets with BinanceSmartChain deployments across 11 paginated requests. BSC RPC bytecode, symbol, and name checks passed for all 1,115 additional contracts. The combined snapshot contains 1,565 distinct `56:contract` identities. Provider-published names and onchain names remain separate; 13 bStocks rows have a name difference beyond the generic “(bStocks)” display suffix.
- **Priority demo coverage:** NVIDIA and TSLA have distinct Ondo, bStocks, and xStocks BSC contracts. AAPL has Ondo and xStocks; no AAPL bStocks row appeared in the checked Binance BSC list. The UI must show two AAPL products rather than infer a missing third. The live Binance exact-contract profile, market, and candle calls succeeded for a bStocks NVDA contract. xStocks is absent from that Binance RWA list, so Mintmark leaves its detailed company and market fields unavailable instead of borrowing another provider's figures.
